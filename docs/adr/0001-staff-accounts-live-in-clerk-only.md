# Staff accounts live in Clerk only, not mirrored to Convex

Staff and Admin Users have no table in `convex/schema.ts` — their list, names, and roles are read live from Clerk on every request (`convex/staffAccounts.ts`), unlike Participants, which are a first-class Convex table. We considered adding a Clerk-to-Convex sync (webhook or write-on-first-login) so Staff would follow the same pattern as Participants, but rejected it: there is no current need to query or join Staff data against other Convex tables, and a live read keeps Clerk as the single source of truth for identity with no sync code to keep correct. Revisit this if a future feature needs to reference a Staff User from another Convex table (e.g. assigning a Staff member to a Trip) or needs to query Staff data outside of what Clerk's API returns.

Writes to a User's role go through Clerk's dedicated `PATCH /users/:id/metadata` endpoint (deep-merges server-side; a key set to `null` is removed) rather than `PATCH /users/:id` with a hand-merged `publicMetadata` object. The latter requires a GET first and replaces `publicMetadata` wholesale, so a concurrent write to any other metadata key racing with it is silently lost — the metadata endpoint avoids that class of bug entirely for role changes.
